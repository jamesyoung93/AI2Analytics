# R and Python parity

A short reference. The R and Python packages expose the same templates
and produce equivalent results on a canonical end-to-end demo. The
showcase HTML carries the headline numbers; this file lists demo
coverage, the full comparison table, what was actually compared, and how
to reproduce.

## Demo coverage

| Use case                         | Python (`.ipynb`)                    | R (`.Rmd`)                            | Paired |
|----------------------------------|--------------------------------------|---------------------------------------|--------|
| Quickstart                       | `00_quickstart`                      | `a_quickstart`                        | yes |
| One template, three regions      | `01_one_template_three_regions`      | `b_one_template_three_regions`        | yes |
| Market mix, budget reallocation  | `02_market_mix_budget_reallocation`  | `c_market_mix_budget_reallocation`    | yes |
| Call optimiser, end-to-end       | `03_call_optimizer_endtoend`         | not yet ported                        | gap |
| Knowledge accumulation           | `04_knowledge_accumulates`           | `d_knowledge_accumulates`             | yes |

The single gap is the call optimiser. The `detail_optimization` template
depends on PuLP plus three random-forest models and is left for a future
R port. The gap is called out in `r-pkg/ai2analytics/README.md`.

## What was compared, and how

The market mix model is the canonical demo because it is fully
deterministic given the data and produces unambiguous numeric outputs
(R squared, per-channel coefficients, ROI). The harness lives under
`parity/`.

A single CSV is generated by `parity/build_shared_data.py` (seed 12345,
156 weeks, 7 columns). Both languages load **the same file**. There is
no independent data regeneration on either side. Both pipelines run with
identical config: ridge regression, alpha = 1.0, default decay 0.5, log
saturation, positive coefficients, intercept on, no standardisation.

Solvers differ. Python uses scikit-learn's `Ridge(positive=True)`;
R uses `glmnet` with `lower.limits = 0`. Bit-identical agreement is not
expected. The tolerances below were chosen so that any future change
that breaks the agreement materially will fail the regression test in
the R suite.

## Pinned by a regression test

`r-pkg/ai2analytics/tests/testthat/test-parity.R` pins the canonical
Market Mix output against the Python reference values. The test skips
gracefully if `parity/shared_mmm.csv` is absent so it stays
CRAN-portable. Assertions:

- R squared agrees within 0.05 absolute
- Per-channel ROI agrees within 20 % relative
- Channel ranking (TV > Digital > Print) is preserved

If a future change to either fitting path breaks the agreement, this
test fires.

## Reproduce

```
parity/
├── build_shared_data.py   # writes parity/shared_mmm.csv (deterministic)
├── run_python.py          # writes parity/python_outputs.json
├── run_r.R                # writes parity/r_outputs.json
└── assert_parity.py       # side-by-side comparison, non-zero exit on failure
```

```bash
python parity/build_shared_data.py
python parity/run_python.py
Rscript -e 'devtools::load_all("r-pkg/ai2analytics", quiet=TRUE); source("parity/run_r.R")'
python parity/assert_parity.py
Rscript -e 'devtools::test("r-pkg/ai2analytics")'
```

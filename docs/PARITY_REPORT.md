**The single gap (call optimizer)** is intentional: the
`detail_optimization` template is not in the R port yet -- it's ~2,000 lines
and depends on PuLP / random-forest stacks that need full R equivalents
(`ompr` or `lpSolveAPI` + `ranger`/`randomForest`). The gap is called out
explicitly in `r-pkg/ai2analytics/README.md`.

## 2. Numerical parity on a shared canonical demo

### Setup

The market mix model was chosen as the canonical demo because:
- It is fully deterministic given the data (no random initialisation).
- It produces unambiguous numeric outputs (R², coefficients, ROI).
- Both packages can load the *same* CSV.

A single CSV is generated by `parity/build_shared_data.py` (seed 12345,
156 weeks, 7 columns) and **both languages load it -- no independent data
regeneration**. The R and Python pipelines are run with identical config:
ridge regression, alpha = 1.0, default decay 0.5, log saturation, positive
coefficients, intercept on, no standardisation.

### Results

| R²                       | 0.7900    | 0.7929    | +0.0029      | ±0.05     | ✓ |
| Adjusted R²              | 0.7786    | 0.7816    | +0.0030      | ±0.05     | ✓ |
| MAPE (%)                 | 4.97      | 4.88      | -0.09 pp     | ±1.0 pp   | ✓ |
| Predicted-sum            | 28811.39  | 28811.39  | 0.0          | <0.1%     | ✓ |
| TV coefficient           | 13.02     | 13.51     | +3.8%        | ±20% rel  | ✓ |
| Digital coefficient      | 7.21      | 7.26      | +0.7%        | ±20% rel  | ✓ |
| Print coefficient        | 1.37      | 1.23      | -9.8%        | ±20% rel  | ✓ |
| TV ROI                   | 1.104     | 1.145     | +3.8%        | ±20% rel  | ✓ |

| Channel ranking by ROI   | TV > Digital > Print | TV > Digital > Print | identical | -- | ✓ |

### What "similar" means here

- **Deterministic structural results** (predicted-sum, channel ranking)
  agree exactly. Both fitting routines satisfy intercept conditions that
  pin sum(predicted) to the data sum.
- **Coefficients** agree within ~10% on every channel. The remaining gap is
  attributable to the solver:
  - **sklearn's `Ridge(alpha=1.0, positive=True)`** uses a
    closed-form / L-BFGS-B style solver minimising
    `||y - Xβ||² + α‖β‖²`.
  - **glmnet's `glmnet(alpha=0, lambda=…, lower.limits=0)`** uses
    coordinate descent on `(1/(2N))·||y - Xβ||² + λ·((1-α)/2)·‖β‖²`.
- **R² agrees within 0.003**, well below any practically interesting
  threshold.

### Bug found and fixed during parity

The R port originally interpreted `alpha` 1:1 as glmnet's `lambda`. With
sklearn's parametrisation, the same `alpha` value implies `λ = α/N` for
ridge. **Fixed in `R/market_mix.R`:** the user-facing `alpha` is now
sklearn-compatible and translated internally to glmnet's lambda. This
brought R² agreement from 0.055 difference down to 0.003 and coefficient
agreement from ~30% to <10%.

The lasso path uses the natural glmnet/sklearn equivalence
(`λ_glmnet = α_sklearn`) which holds without rescaling.

## 3. Regression test in the R suite

`r-pkg/ai2analytics/tests/testthat/test-parity.R` pins the canonical Market
Mix output against the Python reference values. Skips gracefully if
`parity/shared_mmm.csv` is not present (so the test is portable to CRAN).
Asserts:

- R² agrees within 0.05 absolute
- Per-channel ROI agrees within 20% relative
- Channel ranking (TV > Digital > Print) is preserved

If any future change to the R fitting logic breaks parity, this test fires.
The Python side does not need a symmetric test because the Python values
are taken as the reference (`ai2analytics 0.2.0` Python is the authority).

## 4. Operational notes

```
parity/
├── build_shared_data.py    # writes parity/shared_mmm.csv (deterministic)
├── run_python.py           # writes parity/python_outputs.json
├── run_r.R                 # writes parity/r_outputs.json
└── assert_parity.py        # side-by-side comparison; exits non-zero on failure
```

Reproduction:

```bash
python parity/build_shared_data.py
python parity/run_python.py
Rscript -e 'devtools::load_all("r-pkg/ai2analytics", quiet=TRUE); source("parity/run_r.R")'
python parity/assert_parity.py        # prints report; exits 0
Rscript -e 'devtools::test("r-pkg/ai2analytics")'  # 16 test_that blocks / 51 expectations, all pass
```

## 5. Segmentation parity (informal)

Not in the formal parity suite because k-means depends on a random init that
differs between sklearn (`k-means++`, `random_state=42`) and base R
(Hartigan-Wong, no k-means++). On the same `generate_us_hcp(seed=42)` data:

- Python: silhouette ≈ 0.55, segment sizes {0, 1, 2, 3} ≈ {2.0k, 1.4k, 1.0k, 0.6k}
- R     : silhouette ≈ 0.50, segment sizes ≈ similar magnitudes (different label assignment due to random init)

Different seeds and solvers produce different label numbering but
qualitatively similar partitions. A label-invariant comparison (e.g.
adjusted Rand index) would formalise this -- left as future work.

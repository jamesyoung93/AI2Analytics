AI2Analytics — Validation & R-Port Report

AI2Analytics is an AI-assisted framework for scaling pharma analytics pipelines across brands and regions. This pass stress-tested the existing Python demos for Colab/Jupyter portability, built five richer notebooks, shipped a native R port (segmentation, market mix, knowledge, synthetic data), proved numerical parity between the two implementations on a shared canonical demo, and confirmed the working tree and git history are free of secrets, PII, and personal paths.

02Stress Test (Colab / Jupyter portability)

Every existing demo (demos/notebooks/*.py) was run end-to-end in a fresh Python 3.13 environment with the package installed in editable mode. All five passed with no errors.

Colab / Jupyter portability gaps in the legacy scripts

  1. __file__ not defined in notebook cells. Each legacy script does os.path.dirname(__file__) for path setup — a NameError in any Jupyter kernel.
  2. from demos.synthetic_us_hcp import …. The demos directory is not packaged. After pip install ai2analytics the import fails; users would need to git clone first.
  3. Hard-coded relative output paths (demos/data/*.csv) assume a writable repo-relative directory.

Source bug found and fixed

Bug. src/ai2analytics/templates/detail_optimization/output.py:342 called os.makedirs(os.path.dirname(cfg.output_csv), exist_ok=True). When output_csv was a bare filename (no directory part), os.path.dirname returned "" and the call raised FileNotFoundError: [WinError 3] The system cannot find the path specified: ''. Discovered while executing 03_call_optimizer_endtoend.ipynb.

Fix. Changed to os.makedirs(os.path.dirname(cfg.output_csv) or ".", exist_ok=True), matching the pattern already used by the market_mix output module. The notebook now executes cleanly.

Structural fixes

  • Bundled the synthetic generators as a ai2analytics.datasets subpackage. Notebooks now import from ai2analytics.datasets import us_hcp, eu_account, bric and work after a single pip install, with no repo checkout required.
  • Self-installing setup cell in every new notebook: a no-op locally, pulls from GitHub in Colab. No __file__, no out-of-package imports, no hard-coded relative paths.

Bug found and fixed during the parity check

Discrepancy. First parity run showed R² off by 0.055 and per-channel coefficients diverging by up to 30%. Root cause: the R port treated the user-facing alpha 1:1 as glmnet's lambda, but sklearn's Ridge(alpha=…) parametrisation implies λ = α / N for ridge. Different solvers, different effective regularisation strength.

Fix. In R/market_mix.R, the user-facing alpha is now sklearn-compatible and translated internally to glmnet's lambda: gn_lambda = cfg$alpha / N for ridge. Lasso uses the natural one-to-one mapping. Coefficient agreement improved from ~30% gap to <10%; R² agreement improved from Δ = 0.055 to Δ = 0.003.

Regression test

r-pkg/ai2analytics/tests/testthat/test-parity.R pins the canonical Market Mix output against the Python reference values. It skips gracefully when parity/shared_mmm.csv is absent (so the test is portable to CRAN). It asserts:

  • R² agrees within 0.05 absolute
  • Per-channel ROI agrees within 20% relative
  • Channel ranking (TV > Digital > Print) is preserved

If a future change to the R fitting logic breaks parity, this test fires.

Segmentation parity (informal)

Not in the formal suite because k-means depends on a random initialisation that differs between sklearn (k-means++, random_state=42) and base R (Hartigan-Wong, no k-means++). Different seeds and solvers produce different label numbering on the same data, but qualitatively similar partitions. A label-invariant metric (e.g. adjusted Rand index) would formalise this — left as future work.

Recommendations

  • Before publishing release artifacts, double-check that the dist/ contents do not accidentally include notebook files, generated data, or local knowledge stores. [tool.setuptools.packages.find] already points at src, so the wheel should be source-only by construction.
  • Consider adding a pre-commit secret-scanner (gitleaks or detect-secrets) to run the same checks automatically.

07How to Reproduce

# From the repo root.

# 1. Install Python package + dev tools
pip install -e ".[dev]" nbconvert nbclient ipykernel

# 2. Re-execute all five Jupyter notebooks in place
for nb in demos/notebooks/0*.ipynb; do
  jupyter nbconvert --to notebook --execute --inplace "$nb"
done

# 3. R-side install + tests
Rscript -e 'install.packages(c("R6","cluster","dplyr","glmnet","jsonlite",
                              "rlang","tibble","testthat","withr","ggplot2",
                              "knitr","rmarkdown","gridExtra","tidyr"))'
Rscript -e 'devtools::test("r-pkg/ai2analytics")'

# 4. Parity check (Python <-> R)
python parity/build_shared_data.py
python parity/run_python.py
Rscript -e 'devtools::load_all("r-pkg/ai2analytics", quiet=TRUE); source("parity/run_r.R")'
python parity/assert_parity.py

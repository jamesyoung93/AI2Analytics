## Design choices

- **Idiom: R6 + tibble.** R6 fits the stateful pipeline shape (configure,
  run, inspect outputs) better than S4. Outputs are tibbles so they
  cooperate cleanly with `dplyr` / `ggplot2`.
- **Native, not reticulate.** No Python interop. Each pipeline is implemented
  with R-native equivalents: `stats::kmeans`, `cluster::silhouette`,
  `glmnet::glmnet`, `jsonlite`. This avoids deployment friction (no Python
  toolchain on R-only servers).
- **Same surface as Python.** Constructor names mirror the Python classes
  (`SegmentationConfig`, `SegmentationPipeline`, etc.). The
  `dataframes = list(entity_data = df)` pattern is the same as Python's
  `dataframes={'entity_data': df}`.
- **Bundled synthetic data.** `generate_us_hcp()`, `generate_eu_account()`,
  and `generate_bric()` mirror the Python `ai2analytics.datasets` module.
  Distributions are equivalent but not bit-identical (R's RNG and Python's
  NumPy RNG differ).

## What's covered vs. not

| Python feature                         | R port |
|----------------------------------------|--------|
| `templates.segmentation.*`             | yes (`SegmentationPipeline`) |
| `templates.market_mix.*`               | yes (`MarketMixPipeline`) |
| `knowledge.{Decision,Context}Store`    | yes |
| `knowledge.KnowledgeRetriever`         | yes |
| `datasets.{us_hcp,eu_account,bric}`    | yes (`generate_*` functions) |
| `templates.detail_optimization.*`      | **NO** (see below) |
| `AnalyticsSession` (LLM orchestrator)  | NO (see below) |
| `discovery.*` / `conversation.*` / `codegen.*` | NO (depends on AnalyticsSession) |

**Why not detail_optimization?** The Python template is ~2,000 lines and
tightly couples random forests, walk-forward backtesting, and a PuLP linear
program. A faithful R port would mean wiring `ranger`/`randomForest` for the
models and `ompr` + `lpSolveAPI` for the optimizer. That is a substantial
effort and was not in scope for this pass. If desired, recommend porting in
the order: loader → features → models → scoring → optimizer → output, with
checkpoint comparisons against the Python pipeline at each stage.

**Why not AnalyticsSession?** It depends on Databricks/OpenAI HTTP clients
and a discovery/conversation/codegen stack. R has equivalents (`httr2`,
`ellmer`, `chattr`), and we recommend wiring them at the application layer
rather than inside the package -- R users tend to assemble LLM workflows
differently than Python users.
